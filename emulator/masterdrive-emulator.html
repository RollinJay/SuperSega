Master System and Game Gear releases of one title are usually the same engine rebuilt, so their VRAM table bases agree and assets transfer without relocation. The binaries share almost no bytes, so code and level data do not transfer — only assets. The composite always renders the full 256×192, so a Game Gear build appears uncropped.

Operations are classified by shape and frequency. Large aligned rectangles are background work that becomes tile streaming; small frequent ones are objects that become hardware sprites. Erase-and-redraw pairs disappear entirely, because hardware sprites need no restore.

Controls while playing: arrows move, Z fire, X second button, Enter select, Space also fires. Recording samples the tile, colour and object state periodically and timestamps anything you mark, so a labelled playthrough tells the converter which graphics belong to which stage and which are enemies rather than scenery.
Scene boundaries come from palette bursts, screen-sized fills and bank-switch spikes. Object graphics are pulled two ways because engines differ: some push pixels through the CPU port, others copy VRAM to VRAM. Hardware sprites are read straight from the sprite attribute table.

Screens are sampled as you play and every cell is matched against one global tileset, so scenery that repeats across a stage is stored once. Each screen keeps its own name table. When new cells stop appearing the stage has been fully captured.

Edits are applied to the loaded ROM immediately so you can test them, and recorded here for export. Tiles and palettes are found by searching the ROM for their current bytes: a unique match can be patched, several matches need choosing, and no match means the data is compressed or built at runtime and cannot be patched this way. Level layouts, text and music are in per-game formats and are deliberately not offered — there is no generic way to locate them.

A layer copies whatever the game plays on the source channel onto a destination channel, transformed by the settings on that row. The original keeps playing, so you hear both. A delay of one or more frames turns the copy into an echo. Destinations already driven by the game are marked game — writing a layer there means the two will fight for the channel.
Every change is checked against what each machine can physically do. Anything marked Emulator only cannot be built in this hardware family at all — usually because the chip has a single mono output pin and no amount of driver work adds one.
The sound patch is a settings file the enhancement layer applies at runtime — on MasterDrive that is the patch, nothing in the ROM changes. The hardware spec is a written description of the same changes for building a real cartridge patch, which needs the game's sound driver reverse-engineered first.
no gamepad
Gamepads are detected automatically. By default the right face button is A, the bottom one B, the left and top ones C, Start is Start, Select is Pause, and the d-pad and left stick give directions; the left stick always moves the d-pad. Bindings are kept in this browser. In the Master System, Game Gear, SG-1000, SC-3000 and SF-7000 modes A is button 1 and B is button 2 (C is auto-fire when that boost is on), and Start is the Game Gear's Start or, with the Start = Pause boost (on by default), Pause; in MasterDrive mode B is button 1, C is button 2, and A and Start are read through the TH multiplex, as on a Mega Drive pad. Pause does nothing in Game Gear mode.
The 32 KB image is the same layout physical hardware uses, so a card exported here can be written to a real card and back. Saves store only the 256-byte pages a game actually wrote; icons are the player sprite, identified by correlating sprite motion against held input.

These are runtime interceptions, not ROM patches. They watch the standard hardware interfaces every game already uses, so they work on any title with no binary modification and can be toggled mid-frame. Everything except True TMS colours and Start = Pause defaults to stock behaviour; enable one at a time when evaluating a new game.
Sprite limit raise is the highest-value item — sprite flicker is the defining flaw of 8-bit Sega action games and it disappears without touching the ROM. If a game misbehaves, pair it with overflow flag preservation: a few titles read that flag as game logic.

SMS Test Suite
(sverx)		 VDP behaviour, controller input, VDP-type and TV-type detection routines.
Output goes to the Log tab. zexall/zexdoc write to the SDSC Debug Console on ports $FC/$FD, which this emulator implements, so results print as text even if the VDP text rendering is imperfect. They also render to VDP mode 4 when detected, and fall back to TMS9918 text mode otherwise — which means the same ROM exercises the SG-1000 path too.
Expected results, honestly. This core does not implement the internal WZ/MEMPTR register, so the bit n,(hl) test in zexall will fail on its undocumented flag bits — that is the known hard case that trips most emulators, and no SMS or GG game is known to depend on it. Timing is instruction-level rather than cycle-exact within a scanline, so raster-timing tests in the SMS Test Suite may not match hardware.
Search SMS Power! or GitHub for maxim-zhao/zexall-sms and sverx/SMSTestSuite. Load the .sms file through the cartridge picker; no card ROM is needed.
